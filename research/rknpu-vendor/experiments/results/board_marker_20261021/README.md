# 板端首轮 marker 实验（2026-10-21）

板卡：Orange Pi 5 Plus（RK3588），kernel `6.1.43-rockchip-rk3588-rknpu098`，
驱动 `RKNPU v0.9.8`，NPU 频率 1.0 GHz。工作目录 `/mnt/ssd/workspace/rknpu-re/marker/`。
原始产物见 `raw/`（三臂日志、采样 CSV、配对计时、三臂输出 dump）。

负载：`min_conv --dup-config --iw 8`（单 task，合成卷积；`--dup-config` 让
`CNA_CBUF_CON0` 连写两条，制造一个由构造保证的冗余槽位）。
标记槽位计划（发射器自报，规划器离线复核一致）：

```
MARKER_PLAN task=0 slot=1 reg=0x1040 orig=0x0201000000b11040
```

## 1. 已经上板确认的

| 结论 | 证据 |
|---|---|
| **三臂链路可用** | `nop` 与 `marker` 两臂都 `applied=1`、`orig=0x0201000000b11040` 与计划逐字一致、`sync_apply=0`、`MARKER_RESTORE ok=1`（`raw/arms2/*.log`） |
| **长度保持替换对输出无影响** | `nop` 臂（把冗余写换成 OP_NONE）输出与基线**逐字节相同**（`raw/arms2/compare/report.md`） |
| **标记写（PPU 0x6010）对输出同样无影响** | `marker` 臂输出与基线逐字节相同（同上） |
| **主机读回通路可用（限定）** | `CNA 0x1040` 读出 `0x000000b1`，与配置值一致 ⇒ 该地址可读、值可解释。但该样本标为 `task_ambiguous`，**不能**据此认定"读到的就是本 task 刚写入的值"（也可能是持久状态）（`raw/rb_orig_cna.csv`） |
| **重复运行确定性** | 不带 hook 连跑 3 次，输出 md5 完全一致（`e2d2fc14…`） |

## 2. 负面结果（这轮最重要的部分）

**本轮的负面结论必须限定为"未验证成功"，不是"已否定"。** 逐条核对存档后：

| 观察 | 能支持什么 | **不能**支持什么 |
|---|---|---|
| `raw/rb_mk_ppu.csv`：1 个样本，提交后 **44.625 µs**，`task_ambiguous` | marker 臂在该时刻读 `PPU 0x6010` 为 0 | 不能认定样本落在任务执行窗口内，因此不能推出"未使能块的写必然不可见" |
| `raw/rb_orig_cna.csv`：1 个样本，**40.250 µs**，`task_ambiguous` | 该地址可读、值与配置一致（`0xb1`） | 不能排除读到的是**持久寄存器状态**而非本 task 的写入 |
| `raw/rbd_marker.csv`：**只有表头，0 个样本** | 这次运行没有取得任何读回 | 不能据此宣称 DPU `0x40c4` 读回恒零 |
| `raw/rbd_original.csv`：1 个样本，**122.5 µs**（该 task 只跑了 17.5 µs） | 该样本明显在任务结束后 | 不能代表任务内行为 |

准确的结论是：
1. 该合成负载上**三臂输出一致**（改写与恢复机制成立）；
2. PPU 候选**未获得有效窗口内的标记可见证据**；
3. **人工标记落点仍未验证**——既不能判成功，也不能判失败。
因此也不应据此扩大对未命名/未验证寄存器的写探测。

## 3. 两个必须先解决的测量问题

1. **采样相位严重滞后**：请求 `PHASE_NS=2000/10000` 的样本实际落在
   **52.8 / 79.0 / 57.2 µs**（`raw/w_*.csv` 的 `t_ns − submit_enter_ns`）。
   也就是 arm→首次读的延迟约 **50–80 µs**。对 SDPA 那种 ~7 µs 的 task，
   这意味着一次性相位采样**根本落不进任务窗口**，路线 A 的相位扫描必须先把这段延迟压下去
   （候选手段：采样线程绑核 + SCHED_FIFO、预触页、更紧的握手）。
2. **合成任务计时双峰**：`min_conv --iw 8` 交错配对 8 轮，三臂中位数
   17.5 / 20.1 / 18.1 µs，但范围 13.1–96.8 µs。
   早期"marker 臂快 4 倍"是**运行顺序/预热伪影**，交错后消失。
   这样的噪声底远大于任何想要测量的扰动，正式实验必须换低方差负载或大幅增加配对轮次。

## 4. 与之前结论的关系

- 上轮的"PPU 是唯一既有依据的注入落点"仍然成立（它确实从不被使能），但**不被使能同时也意味着
  写进去看不到**，这条路线在 RK3588 + 0.9.8 上**没有走通**。
- `min_conv --dup-config` 证明"长度保持替换"这条工程路径可用；
  卡住的是**标记寄存器本身**，不是改写机制。
- 三臂输出比对、`--expect-orig` 前置校验、同步/恢复状态上报都在板端按设计工作。

## 5. 已确定的方向（2026-10-21 决定）

**暂停扩展人工标记写入**，顺序改为：先把采样时序做可信 → 再验证 B0 自然标记 →
时序与 bank 都通过后，才重测同一个 PPU 候选。

1. **先拆延迟，不直接堆调度优化**：记录 `arm_observed`、相位等待结束、电源检查起止、
   首次 MMIO 起止；绑核 / 预触页 / 预开 fd 分别做对照；`SCHED_FIFO` 后置，
   且不得挤占提交线程或完成中断；**不能以关闭电源保障换低延迟**。
2. **先用长任务校准**（本轮的 `--iw 32`），验收指标改成
   **窗口覆盖率、采样迟到分布、读取区间宽度**；`<2 µs` 作为短任务目标时约束的是迟到与抖动，
   不是要求所有样本都落在 submit 后 2 µs 内。
3. **B0 自然标记**：从已证明可读的 CNA 配置出发，用不同运行/不同 task、bank 构造可区分值，
   验证旧值→新值与持久窗口；bank 未分清前只报观测，不推断命令到达。
4. **最后**才用已确认的有效窗口重测 PPU 候选；仍不可见时，负结果限定到该寄存器、
   该配置与该驱动版本。

完整捕获的 78 条、驱动 PM/job 生命周期、submit→kick 偏移仍未处理。

# 单 task 内的多快照：边沿夹逼

`CAP>1` 时一次提交内取多个快照，因此窗口的上升/下降可以被**同一次运行**里的相邻两个快照夹住，不需要逐次运行的平稳性假设。

边沿按**读取区间**保守包围：每次快照的值是在它自己的 `[gb, ge]` 之内读到的，不是 `t_ns` 那一个瞬间。因此 clear→set 的转变 `T` 满足 `gb(clear) < T <= ge(set)`，反向同理。只用 `t_ns` 会得到比读取能力更窄的区间。

**注意**：下面的「间隔」是间隔本身的分位数，**不是精度保证**，也不构成 ±X µs 的误差界。

| 指标 | p10 | p50 | p90 |
|---|---|---|---|
| 每次运行的快照数（中位数） | 22.5 |
| 相邻快照间隔 (µs) | 2.04 | 2.62 | 6.33 |
| 单次读取区间 (µs) | 0.88 | 1.17 | 2.04 |
| 覆盖跨度 (µs) | 54.02 | 81.23 | 99.08 |
| 首个快照 (µs) | 8.78 | 9.19 | 19.25 |

- 运行数：12
- **分位数口径**：上表用线性插值；若按 **nearest-rank**（上中位数）复算，同一批数据为：快照数 23、间隔 p90 6.42 µs、跨度 p50 84.58 µs、首个快照 p50 9.33 µs。两种口径都列出，避免与他人复算结果对不上。
- 上升沿被夹住的运行：9
- 下降沿被夹住的运行：8
- 同一次运行内出现 **≥3 段**（clear→set→clear 这类完整窗口）：**8/12**
- 两边沿都被夹住：8（其中位窗口宽度下界中位数 6.85 µs）

## 没有证明的

- 边沿是**区间**，宽度由相邻快照的读取区间决定；「间隔中位数」不是误差界；
- 首个快照仍有一个约 9 µs 的下限，任务最开头不可观测；
- 不涉及任何 regcmd 位置或 per-regcmd 时长；
- 结论仅适用于本板、本驱动版本与该负载。

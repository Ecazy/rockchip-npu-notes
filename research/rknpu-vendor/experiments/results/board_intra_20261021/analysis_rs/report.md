# 单 task 内的多快照：边沿夹逼

`CAP>1` 时一次提交内取多个快照，因此窗口的上升/下降可以被**同一次运行**里的相邻两个快照夹住，不需要逐次运行的平稳性假设。

边沿**只给区间**：上升 ∈ (最后一次 clear, 第一次 set]，下降 ∈ (最后一次 set, 第一次 clear]。

| 指标 | p10 | p50 | p90 |
|---|---|---|---|
| 每次运行的快照数（中位数） | 32 |
| 相邻快照间隔 (µs) | 2.33 | 2.62 | 3.50 |
| 单次读取区间 (µs) | 0.88 | 1.17 | 1.17 |
| 覆盖跨度 (µs) | 43.75 | 79.92 | 88.38 |
| 首个快照 (µs) | 9.04 | 9.62 | 14.29 |

- 运行数：36
- 上升沿被夹住的运行：25
- 下降沿被夹住的运行：32
- 同一次运行内出现 **≥3 段**（clear→set→clear 这类完整窗口）：**25/36**
- 两边沿都被夹住：25（其中位窗口宽度下界中位数 37.04 µs）

## 没有证明的

- 边沿精度受相邻快照间隔限制，不是点值；
- 首个快照仍有一个约 9 µs 的下限，任务最开头不可观测；
- 不涉及任何 regcmd 位置或 per-regcmd 时长；
- 结论仅适用于本板、本驱动版本与该负载。

# 单 task 内的多快照：边沿夹逼

`CAP>1` 时一次提交内取多个快照，因此窗口的上升/下降可以被**同一次运行**里的相邻两个快照夹住，不需要逐次运行的平稳性假设。

边沿**只给区间**：上升 ∈ (最后一次 clear, 第一次 set]，下降 ∈ (最后一次 set, 第一次 clear]。

| 指标 | p10 | p50 | p90 |
|---|---|---|---|
| 每次运行的快照数（中位数） | 8 |
| 相邻快照间隔 (µs) | 2.92 | 3.21 | 8.75 |
| 单次读取区间 (µs) | 0.88 | 1.17 | 2.04 |
| 覆盖跨度 (µs) | 23.92 | 34.71 | 42.00 |
| 首个快照 (µs) | 9.04 | 11.67 | 30.04 |

- 运行数：20
- 上升沿被夹住的运行：4
- 下降沿被夹住的运行：5
- 两边沿都被夹住：3（其中位窗口宽度下界中位数 9.62 µs）

## 没有证明的

- 边沿精度受相邻快照间隔限制，不是点值；
- 首个快照仍有一个约 9 µs 的下限，任务最开头不可观测；
- 不涉及任何 regcmd 位置或 per-regcmd 时长；
- 结论仅适用于本板、本驱动版本与该负载。

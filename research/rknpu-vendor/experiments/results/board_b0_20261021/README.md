# B0 自然标记：板端观测（2026-10-21）

目标：已证明**可读**的 CNA 配置寄存器能不能当作"命令位置"的自然标记。
判据不是"值对不对"，而是**本 run 写的新值什么时候能被主机看到**。

- 负载：`min_conv`（单 task），`CNA_DATA_SIZE2 = 0x1028`，写入值随输入宽度变化：
  `iw=16→0x10`、`iw=32→0x20`、`iw=64→0x40`、`iw=96→0x60`（由 `--dump-rows` 离线确认，不是猜的）。
- 采样：`RAW_OFF=0x1028`、`CAP=1`、`PREOPEN_POWER=1`（上一轮拆解出的低延迟组合）。
- 每个 run 一个新进程；同一进程多次 submit 的版本尚不存在（见下文限制）。
- 原始数据：`b0/`（14 次随机配对，iw∈{16,32}）、`b0late/`（相位 55 µs，多数落空）、
  `b0long/`（12 次随机配对，iw∈{64,96}，任务更长）。

## 1. 结果

**第一组（iw∈{16,32}，14 次，13 次落在窗口内）**

| 观察 | 次数 |
|---|---|
| 读回值 == 本 run 配置值 | 9 |
| 读回值 == 上一次 run 的配置值（且两者不同） | 4 |
| 其它（更早的残留值） | 1 |

**关键：所有 5 次"值真的发生了变化"的 trial，读回的都是旧值**，包括落在窗口内
8.8–22.5 µs 的样本。

**第二组（iw∈{64,96}，任务更长，12 次全部有样本）**

| trial | 本 run 写 | 上次写 | 读回 | 相位 | 任务时长 | 相位/时长 |
|---|---|---|---|---|---|---|
| g02 | 0x60 | 0x40 | **0x40** | 26.8 µs | 28.3 µs | **95%** |
| g12 | 0x60 | 0x40 | **0x40** | 30.9 µs | 37.0 µs | 83% |
| g03 | 0x40 | 0x60 | **0x60** | 37.0 µs | 62.7 µs | 59% |
| g01 | 0x40 | 0x20 | **0x20** | 29.2 µs | 66.2 µs | 44% |

`g02` 最有说服力：样本落在任务 **95%** 处——配置写（流内 slot 11）早已发出，
"采样早于写入"已经很难再解释它。而**下一次相同配置的 run** 才读到新值
（如 g03 写 0x40 后，g04 读到 0x40）。

## 2. 可以下的结论（只到观测层）

1. `CNA 0x1028` 确实**可读**，且值**随配置变化、跨 run 持久**。
2. 在"一个 run 一个 task"的设置下，读回**滞后整整一个 run**：本 run 写的新值，
   在**下一个 run** 才被主机看到；本 run 看到的是上一个 run 留下的值。
3. 因此这个寄存器**不能**用来标记"本 run 内某条命令已经执行"——至少在当前
   读回方式下不能。

**没有**下结论的部分（按约定）：滞后一个 run 究竟是"主机固定读某一组、写入按
ping-pong 交替"，还是别的原因，本轮数据**区分不了**；这需要能控制 `S_POINTER`/bank 的
实验，或同一进程内多 task 的流。

## 2b. 同一次 submit 内的双 task（区分 run 级 / task 级滞后）

用 `min_chain --tasks 2`：**一次 submit 两个 task**，两个 task 的输入地址天然不同
（task0 = `act` = `0xffff0000`，task1 = `mid` = `0xfffe8000`），且都会写
`CNA_FEATURE_DATA_ADDR (0x1070)`。因此读回 `0x1070` 就能判断主机看到的是哪个 task 的配置。
原始数据在 `b0chain/`、`b0chain2/`。

**"两个 task 都执行"这一条不成立（已撤回）**：`ret=0` 与耗时增加都不能证明执行正确。
复查发现 `min_chain` 自己的数值校验**每次都报 `MISMATCH`**（12/12）：

```
trial 1..12   RESULT: MISMATCH
```

因此下面这些读数只能算**该配置下的原始观测**，不能作为"已验证负载上的结论"。

**采样结果**：

| 分类 | 样本 | 读到 task0(act) | 读到 task1(mid) |
|---|---|---|---|
| 落在窗口内（最高 95%） | 12 | **12** | **0** |
| 落在窗口后 | 17 | 17 | 0 |

即：在一次 submit 内，**主机始终读到 task0 的配置**。

> 评审修正：原文写"即使样本落在窗口 95% 处"，但 `相位/hw_elapse` 的时间归属已撤回
> （分子分母无共同起点，见测量模型 §5），因此这里**只保留"从未读到 task1 配置"这一观测**，
> 不再用它推断"命令已到达何处"。

**观测层结论**：读回**从不显示当前 task 正在写的配置**，而是显示上一个 task 的；
单 task/run 实验里"值晚一个 run 出现"与这里"晚一个 task"是同一现象。
机理（是否 ping-pong 每 task 换组）仍未证明。

**`--tasks 4` 的超时是探针构造问题，不是硬件证据（已修正）**：`min_chain.c` 只初始化
`t[0]`、`t[1]` 两个描述符和两段命令流（`memset(t, 0, 2 * sizeof(*t))`），
`--tasks 4` 却直接把提交数量改成 4。现在源码已在该参数下**直接拒绝**
（`--tasks must be 1 or 2`）。超时本身不再作为链能力的负面证据。

## 2c. 双寄存器采样与计数器复核（修正版）

### 计数器与有效性（对 20 个文件、19 条样本逐条统计）

| `c0_ts` | 条数 |
|---|---|
| `0x0000f000`（低 12 位 = 0） | 16 |
| `0x0000a001`（低 12 位 = **1**） | 3 |

| `sample_validity` | 条数 |
|---|---|
| `task_ambiguous` | 16 |
| `ok` | 2 |
| `task_crossed` | 1 |

**所以不能说"计数器恒为 0xf000"**：有 3 条样本计数器推进到了 1，其中 2 条 `task_before ==
task_after == 1` 判为 `ok`。这三条是整批数据里唯一"确定在 task 1 内"的观测：

| 样本 | 计数器 | 有效性 | `0x1070` 读回 |
|---|---|---|---|
| p2000_r0 | 1 | ok | `0xffff0000`（**task0 的输入**） |
| p2000_r3 | 1 | ok | `0xffff0000`（**task0 的输入**） |
| p2000_r1 | 1 | task_crossed | `0xffff0000` |

补充复跑 12 次（`inwin/`，同时记录负载自身的 `RESULT`）：`ok` 样本 2 条，计数器均为 1，
读回均为 task0 的地址；但**全部 12 次 `RESULT: MISMATCH`**。

因此在**该未通过数值校验的配置**下：task 1 运行期间主机读到的是 task0 的配置。
这条只能在"负载未验证"的前提下陈述。

### `S_POINTER` 判组

本负载的命令流里**没有** CNA `S_POINTER (0x1004)` 的写（`min_chain.c:255` 只发 DPU 和
DPU_RDMA 的指针写）；CNA 指针按仓库既有记录由驱动在提交时写。所以：

- `0x1004` 读回恒 0 **不等于**"该寄存器不可读"，只能说明**在本配置下它没有提供可判组的信号**；
- "读指针判组"这条路**本配置下未建立**，但不判其永久不可行。

给 hook 加了 `RAW_OFF2`（同一次采样读第二个寄存器，预算 +1），在一次 2-task submit 里
**同时**读 `CNA_FEATURE_DATA_ADDR (0x1070)` 和 `CNA_S_POINTER (0x1004)`，
5 个相位 × 4 次。原始数据在 `b0ptr/`。

| 观察 | 结果 |
|---|---|
| `0x1004` 读回值 | **19/19 次都是 `0x00000000`**，尽管两个 task 的流里都写了 `0x0E` |
| `0x1070` 读回 `task0(act)` | 19/19 |
| `0x1070` 读回 `task1(mid)` | **0/19**，包括 `frac=430%`（任务早已结束）的样本 |

结论（限定语已按复核收紧）：
1. **本配置下未建立可解释的组信号**：`0x1004` 恒 0，且该偏移本来就没有命令流写入。
   不据此判定"该寄存器不可读"或"S_POINTER 判组永久不可行"。
2. **撤回"任务结束后应追上最后一笔写"的推理**：按 task/bank 切换暴露上一组的机制，
   没有后续 task 时本就不一定刷新；因此不能用"结束后仍读 act"排除按拍滞后的机制。
3. **撤回 `frac = 相位/hw_elapse` 的"已在任务之后"判据**：分子从用户态 submit 入口起算，
   分母是驱动报告的持续时间，两者没有共同的起点证据。

## 3. 限制

- 双 task 实验已补上"task 级"这一层；仍未做"同一进程内多次 submit"的多轮实验。
- 无法从时间上定位 task 边界（任务计数器 `0x003c` 在本负载上恒为 `0xf000`，
  低 12 位不随 task 推进），所以"early/late"只能按窗口比例近似，不能精确到 task。
- 相位抖动仍大（相位 = 请求 φ + 8–25 µs 迟到），`frac > 100%` 的样本落在任务之后，
  已在下结论时剔除。
- 任务时长双峰（15 µs / 70 µs），固定 φ 会随机落空，第二组改用更大负载缓解。

## 4. 对路线的意义

- B0 的"自然标记"需要一个**在本 run 内可观测**的量。当前这个寄存器做不到，
  除非能控制 bank 或读到两组。
- 下一步要么（a）做同进程多 task 的流并按 task 观察，要么（b）先解决 bank
  （读 `S_POINTER` + 判断主机读哪一组），要么（c）换一种读回量（例如模块状态字）。
- 人工标记写入仍按上一轮决定**暂停**，不动。
